     Plan: apps/web frontend (React + Vite + Eden Treaty)

     Context

     The API is done (apps/api, Elysia 1.4, export type App in
     apps/api/src/index.ts). We need a small React UI with two tabs, Filings and
     Summary, that calls the API through Eden Treaty. It should import only the
     App type, send calls through the Vite dev proxy (no CORS), use no router
     or UI library, and add no new dependencies. Nothing in apps/api changes.

     What I found (read-only checks)

     - @elysiajs/eden@1.4.9 is already in apps/web/package.json, so no 
       package.json changes are needed.
     - I type-checked apps/api/src/index.ts with the web compiler options (web
       tsc 6.0.3 + --strict). It passes except for erasableSyntaxOnly:
       apps/api/src/sec.ts:14 uses a constructor parameter property (public 
       code) in AppError. Since import type still type-checks the API source,
       the web tsconfig must drop that flag.
     - tsconfig.app.json has no "strict": true. Eden Treaty needs strict mode to
       infer types correctly.
     - Bun installed two physical copies of elysia@1.4.32
       (node_modules/.bun/elysia@1.4.32+56e7… used by api, +0034… used by eden).
       The dist files are identical, but Elysia has private members, so TS may
       reject treaty<App> (the "separate declarations of a private property"
       error). This is unverified because I couldn't write a probe file in plan
       mode. I'll check it first thing (step 1). The fix is a tsconfig paths
       entry, below.
     - The root bun run dev already runs --filter './apps/*' dev, so it starts
       both the API and Vite.

     Config changes (need your OK)

     1. apps/web/tsconfig.app.json (required)

          "noEmit": true,
          "jsx": "react-jsx",

          /* Linting */
     +    "strict": true,
          "noUnusedLocals": true,
          "noUnusedParameters": true,
     -    "erasableSyntaxOnly": true,
          "noFallthroughCasesInSwitch": true

     2. apps/web/tsconfig.app.json (only if step 1 shows the duplicate-elysia 
     error)

          "noEmit": true,
          "jsx": "react-jsx",
     +    "paths": { "elysia": ["../api/node_modules/elysia"] },
     This makes eden's import type { Elysia } from 'elysia' resolve to the same
     copy the API uses. It is types only and has no runtime effect, because
     eden's runtime doesn't import elysia in the browser.

     3. apps/web/vite.config.ts (not package.json/tsconfig, shown for clarity)

     export default defineConfig({
       plugins: [react()],
       server: {
         proxy: {
           '/api': {
             target: 'http://localhost:3000',

           },
         },
       },
     })
     The /api prefix keeps API paths separate from frontend paths. The API
     itself has no /api prefix, so the proxy strips it.
